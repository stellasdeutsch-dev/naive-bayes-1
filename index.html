why you will understand it

five small tools first. every one has a tiny example and a “try it”.

1

a classifier answers p(class | features)

The class c is toxic (T) or friendly (F). The features are a vector x = (x₁, …, x_D): here x_j = 1 if word j is in the message, else 0. D = 4 words: ez, noob, gg, wp.

try it: write x for “gg wp”

(ez, noob, gg, wp) = (0, 0, 1, 1).

2

Bayes' rule turns it around

p(c | x) = p(x | c) · p(c) / p(x)

p(c) is the class prior (how common toxic is). p(x | c) is the class-conditional: how likely these words are in a toxic message. p(x) is the same for every class.

3

“generative” means: describe how each class produces data

We model p(x | c) and p(c), then use Bayes' rule. (A discriminative model like logistic regression models p(c | x) directly; that comes on Day 14.)

4

Bernoulli for one yes/no word

p(x_j | c) = θ_jcx_j (1 − θ_jc)1 − x_j

θ_jc = chance that word j appears in a class-c message. Word there: factor θ_jc. Word missing: factor 1 − θ_jc.

try it: θ = 0.75, word missing. factor?

1 − 0.75 = 0.25.

5

“∝” and normalising

If the two scores are s_T and s_F, then p(T | x) = s_T / (s_T + s_F). Dividing by the sum is the same as dividing by p(x). To just pick a class, compare the scores; no division needed.

remember it: classify with Bayes' rule: p(c | x) ∝ p(c) · p(x | c). The whole lecture is about making p(x | c) easy.

the naive idea: words are independent given the class

p(x | c) is a probability for a whole vector of words. With D words there are 2D possible vectors; with 600 words that is more than the number of atoms in the universe. You can't count all of them.

The naive Bayes assumption: once you know the class, the words don't influence each other. Then p(x | c) splits into one small factor per word:

p(x | c) = Πj p(x_j | c)

It is called “naive” because it is usually not exactly true (in toxic chat, “ez” and “noob” come together). It still works surprisingly well, and it needs only D numbers per class instead of 2D − 1.

fitting = counting

What we need: the class priors π_c and, for every word j and class c, θ_jc. The MLE (maximum likelihood) answer is simply a share:

π̂_c = N_c / N     θ̂_jc = N_jc / N_c

N_c = messages in class c. N_jc = messages in class c that contain word j. In words: “how many toxic messages contain ez, out of all toxic messages”.

one messagep(xᵢ, cᵢ) = πcᵢ Πj θj,cᵢxᵢⱼ(1 − θj,cᵢ)1−xᵢⱼclass prior × naive product
all datalog p(D) = Σc N_c log π_c + Σc Σj [N_jc log θ_jc + (N_c − N_jc) log(1 − θ_jc)]log of a product = sum; group by class and word
each θ aloneN_jc/θ − (N_c − N_jc)/(1 − θ) = 0exactly the Mirana hit-rate derivative (Lecture 2)
solveθ̂_jc = N_jc / N_c,   π̂_c = N_c / Nπ is a Categorical MLE (counts ÷ total)
classπ̂ = N_c/Nθ̂ ezθ̂ noobθ̂ ggθ̂ wp
toxic N_T = 44/10 = 0.43/4 = 0.753/4 = 0.752/4 = 0.50/4 = 0
friendly N_F = 66/10 = 0.61/6 ≈ 0.170/6 = 05/6 ≈ 0.835/6 ≈ 0.83

remember it: π̂_c = N_c/N and θ̂_jc = N_jc/N_c. Fitting naive Bayes takes one pass over the data: O(N·D).

predicting, step by step

p(c | x) ∝ π_c · Πj θ_jcx_j (1 − θ_jc)1 − x_j
message“ez gg” → x = (1, 0, 1, 0)ez yes, noob no, gg yes, wp no
toxic score0.4 · 0.75 · (1 − 0.75) · 0.5 · (1 − 0) = 0.0375θ for present words, 1 − θ for missing
friendly score0.6 · (1/6) · (1 − 0) · (5/6) · (1 − 5/6) ≈ 0.0139same recipe with friendly θ's
normalisep(T | x) = 0.0375 / (0.0375 + 0.0139) ≈ 0.7373% toxic → predict toxic

three messages, three lessons

“ez gg”: 73% toxic. A normal case.

“gg wp”: toxic score = 0.4 · … · θ_wp,T = 0 because no toxic message ever had wp. Result: 100% friendly, overconfident.

“noob wp”: toxic score 0 (wp), friendly score 0 (noob). 0/0: the classifier crashes. Fixing this is part 2.

remember it: score each class = prior × product of word factors; pick the biggest; divide by the sum for probabilities. A single zero θ kills a class.

the log-sum-exp trick

With 600 words you multiply 600 numbers below 1. The product is like 10−200, and a computer rounds it to 0 (underflow). Fix: work with logs. Let

b_c = log p(x | c) + log p(c)

To pick a class, take the biggest b_c. Done, no trick needed. To get probabilities you need log Σ eb_c, and e−120 already underflows. Pull out the biggest term B = max b_c:

log Σc eb_c = B + log Σc eb_c − B

Example: log(e−120 + e−121) = −120 + log(e⁰ + e−1) = −120 + log 1.368 ≈ −119.69. Every number stays readable. Then log p(c | x) = b_c − log Σ eb_c′.

remember it: to classify, compare log scores; for probabilities, subtract the max before exponentiating.

learn it by heart

trap 1 · forgetting missing wordsA word that is NOT in the message still counts, with factor 1 − θ_jc (Bernoulli model).
trap 2 · forgetting the priorMultiply by π_c. A rare class needs much stronger word evidence.
trap 3 · wrong denominatorθ̂_jc divides by N_c (messages of that class), not by N.
trap 4 · normalising too earlyCompute both scores first, then divide each by their sum.
trap 5 · thinking “naive” = wrongThe assumption is false in reality but the classifier still works well, especially with little data.
trap 6 · ignoring zerosOne θ̂ = 0 or 1 can make a score exactly 0. Part 2 fixes it with priors.
p(c|x)
explain it back
what does “naive” mean in naive Bayes?

The features are assumed independent given the class, so p(x | c) = Π p(x_j | c).

why is it called a generative classifier?

It models how each class generates the data, p(x | c) and p(c), and then uses Bayes' rule to get p(c | x).

how do you fit a Bernoulli naive Bayes?

Count: π̂_c = N_c/N and θ̂_jc = N_jc/N_c. These are the MLEs.

how do you classify a new message?

For each class multiply π_c by θ_jc for present words and 1 − θ_jc for missing words; pick the largest; divide by the sum for probabilities.

why use logs, and when do you need log-sum-exp?

Products of many small numbers underflow. Logs turn them into sums. Log-sum-exp is only needed for normalised probabilities; for the arg max, compare log scores directly.

practice problems

01easy

parameters to count

A Bernoulli NBC with D = 20 words and C = 3 classes. How many parameters does it have? How many would a full model of p(x | c) need?

hint

NBC: one θ per word and class, plus the class prior. Full: a probability for every vector in {0,1}D.

solution
  • NBC: C·D = 60 values θ_jc, plus C − 1 = 2 for π: 62
  • Full: C(2D − 1) = 3 · 1 048 575 ≈ 3.1 million (Week 6, Q1)
02easy

fit by counting

Add two new messages to our data: “noob” (toxic) and “gg” (friendly). Recompute π̂ and θ̂ for the word noob in both classes.

hint

N_T = 5, N_F = 7, N = 12.

solution
  • π̂_T = 5/12, π̂_F = 7/12
  • θ̂_noob,T = 4/5 = 0.8; θ̂_noob,F = 0/7 = 0

classify “ez noob gg”

Using the table from this lecture, compute both scores and p(toxic | x) for x = (1, 1, 1, 0).

04medium

prior beats evidence

Two classes, π_T = 0.1, π_F = 0.9. One word: θ_T = 0.5, θ_F = 0.125. The word appears. Which class wins? (Week 5, Q2 idea)

hint

Compare 0.1 · 0.5 with 0.9 · 0.125.

solution
  • T: 0.05; F: 0.1125
  • p(T | x) = 0.05/0.1625 ≈ 0.31 → friendly, although the word is 4× more common in toxic chat

pass or fail, the original numbers

D = {(F,1,1), (F,0,0), (P,1,1), (P,1,0), (F,0,1), (F,1,0), (P,1,1)} with features (attended, homework). Fit the MLE NBC and classify (1, 1).

Same numbers as the Dota exam box, with P = W.

06challenge

log-sum-exp by hand

Log scores b_T = −300, b_F = −302. Compute log p(T | x) and p(T | x) without underflow.

hint

B = −300.

solution
  • log Σ = −300 + log(1 + e−2) = −300 + log 1.1353 ≈ −299.873
  • log p(T | x) = −300 − (−299.873) ≈ −0.127 → p ≈ 0.88
